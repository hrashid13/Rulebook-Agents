# Rulebook Agents: design for v1

Status: M0 and M1 built (`rulebook policies`, `rulebook review` locally). Everything from M2 on is still design.

## What it is

A GitHub Action (and a small CLI) that lets a team write its coding rules in plain English and have them enforced on every pull request.

1. **Rules:** an agent turns each written policy into a Semgrep rule, tests it, and opens a pull request adding it. Merging that PR is the human approval.
2. **Review:** on every pull request, Semgrep scans the changed lines, one agent separates real problems from noise, and a second agent explains each real problem and quotes the policy it breaks.
3. **Report:** one comment on the PR, updated on every push, plus a check result. A maintainer can turn any finding into a GitHub issue with a comment command.

Any language Semgrep supports. Any model with an Anthropic or OpenAI-compatible API, including a self-hosted one.

## Not in v1

- Fixing code automatically or pushing commits to the PR.
- Blocking merges by default (the check can be set to fail, but the default is advisory).
- Running on pull requests from forks (GitHub does not give them secrets; we skip with a note).
- An MCP server, an IDE plugin, a hosted service.

## What a user adds to their repo

```
.rulebook/
  policies.md          written by the team: one policy per "##" heading
  config.yml           optional settings (model, paths, fail_on, ...)
  rules/               generated by the rules flow, reviewed and merged like any code
    no-thread-abort.yml
    no-thread-abort.cs         Semgrep test file for that rule (ruleid: / ok: annotations)
.github/workflows/rulebook.yml
```

Plus one repo secret, `ANTHROPIC_API_KEY` (or `RULEBOOK_API_KEY` for another provider).

### `policies.md`

```markdown
## No Thread.Abort
category: bug_risk
languages: csharp
severity: error

Do not call Thread.Abort() in managed code. Use a CancellationToken for cooperative cancellation.

## Parameterized SQL only
category: security
languages: python, java, typescript

SQL must be built with parameters or an ORM, never by concatenating or formatting strings.
```

- The heading is the policy's title; its id is the heading as a slug (`no-thread-abort`). Ids are stable and readable, and two people adding policies never collide on numbers.
- `category` (security, bug_risk, style), `languages` and `severity` are optional. Missing languages default to the repo's languages from `config.yml`.
- The text under the fields is the rule text that findings quote word for word.

### `config.yml` (every field optional)

```yaml
languages: [python, typescript]   # default: detected from the repo
paths: { include: [src/], exclude: [tests/fixtures/] }
model: claude-haiku-5-5           # provider: anthropic | openai
fail_on: none                     # none | error | any  (when the check fails)
max_findings: 25                  # per PR, to bound cost
issues: command                   # off | command   (/rulebook file N)
```

### The workflow file

```yaml
name: Rulebook
on:
  pull_request:                  # review flow
  push:
    branches: [main]
    paths: [.rulebook/policies.md]   # rules flow
  workflow_dispatch:             # rules flow, by hand
  issue_comment:
    types: [created]             # /rulebook file N
permissions:
  contents: write                # rules flow opens a branch
  pull-requests: write
  issues: write
jobs:
  rulebook:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: hrashid13/Rulebook-Agents@v1
        with:
          api-key: ${{ secrets.ANTHROPIC_API_KEY }}
```

One workflow, one Action; the Action reads the event and runs the matching flow.

## Flow 1: rules (policy text -> reviewed Semgrep rules)

Trigger: `policies.md` changes on the default branch, or a manual run.

1. Parse `policies.md`. Compare each policy with `rules/` by id and a hash of its text: new, changed, removed.
2. For each new or changed policy and each of its languages, the rule synthesizer drafts a Semgrep rule **and** a test file with `ruleid:` lines (must match) and `ok:` lines (must not).
3. Code checks it: valid YAML, one rule, the expected id, then `semgrep --test`. Failures go back to the model, up to 3 attempts.
4. Open (or update) one pull request, "Rulebook: 2 new rules, 1 changed". The PR body shows each policy, its rule, and its test result. Policies that failed after 3 attempts are listed as "needs a hand-written rule". Removed policies delete their rule files.
5. A human reviews and merges. **Merging is the approval**: nothing reaches `rules/` any other way. Branch protection and CODEOWNERS make that as strict as the team wants.

Notes:
- The repo must allow Actions to create PRs (Settings > Actions > "Allow GitHub Actions to create and approve pull requests"); the Action says so clearly if it is off.
- A PR opened with the default token does not trigger other workflows. That is fine here: the review flow has nothing to scan in a rules-only PR.
- `semgrep --test` also runs in the review flow, so a hand-edited rule that breaks its own test is reported.

## Flow 2: review (every pull request)

1. Read the policies and rules **from the base branch, not the PR**. Otherwise a PR could delete the rule it breaks, or edit a policy's text (which the agents treat as trusted) to carry instructions. Changes to `.rulebook/` itself are reviewed by people, like any code.
2. Compute the changed lines from the PR's base...head diff.
3. Run Semgrep with `.rulebook/rules/` on the changed files; keep alerts on changed lines; cap at `max_findings`.
4. **Agent 1 (triage)**: for each alert, the rule, the policy text, and ±12 lines of the file with the flagged line marked. Real problem or noise, with a reason. Code under review is untrusted input (tagged, sanitised, injection phrases block a dismissal).
5. **Agent 2 (explain and cite)**: for each real problem, the policy its rule came from is known in code (rule id -> policy id), so it is handed over, not searched for. Agent 2 writes a short explanation, quotes the sentence of the policy that applies, and suggests a fix. Code checks the quote is word for word in that policy; if not, retry once, then fall back to the policy's first sentence and say so.
6. Post or update one PR comment (found by a hidden marker), and set the check result from `fail_on`.

The comment:

```
Rulebook Agents found 2 problems in this PR (1 alert dismissed as noise)

1. src/db/users.py:42  [security] Parameterized SQL only
   > SQL must be built with parameters or an ORM, never by concatenating or formatting strings.
   The query concatenates `user_id` from the request into a DELETE statement.
   Suggested fix: cursor.execute("DELETE FROM users WHERE id = %s", (user_id,))

2. ...

Dismissed: tests/fixtures/seed.py:10 (test data, not production code)
Maintainers: comment `/rulebook file 1` to open an issue for a finding.
```

Everything the models wrote is escaped before posting: no @mentions, no links, no HTML. A model must never be able to ping people or post a link through our comment.

## Flow 3: issues on command

Trigger: a PR comment `/rulebook file 1` (or `file all`).

1. Check the commenter has write access or higher; otherwise reply that they can't.
2. Read the findings from the hidden data block in our own PR comment (no model call).
3. Open an issue per finding: title from the policy, body with the PR link, file and line, the quote and the explanation; label `rulebook`. Skip findings already filed for this PR.

## Security model

| Risk | Control |
|---|---|
| Untrusted PR code steals secrets | Only `pull_request`, never `pull_request_target`; fork PRs get no secrets and are skipped |
| Prompt injection in the PR makes the model act | Models hold no GitHub token and call no tools. Only plain code posts comments, opens PRs and issues, from validated output |
| Injection makes Agent 1 dismiss a real problem | Tagging, sanitising, quarantine on injection phrases; the "dismissed" list is shown in the comment so a human can see it. Residual risk, documented |
| Model output pings people or posts links | All model text escaped before posting |
| Someone files issues they shouldn't | `/rulebook file` checks the commenter's permission |
| A bad rule slips in | Rules only arrive by merged PR, each with a passing `semgrep --test` |
| Runaway cost | `max_findings`, a per-run call cap, and a cache of answers keyed by the prompt (unchanged lines on the next push cost nothing) |

## What we reuse from Docker Locker, and what we drop

| Reuse (generalised) | Drop |
|---|---|
| Agent 1 triage prompt, guardrails, fail-closed errors | Contoso samples, C#-only prompts |
| Agent 2 output contract and quote check | Chroma and the embedding model: the rule -> policy mapping is exact, so v1 needs no search (smaller, faster image) |
| Rule synthesizer loop and Semgrep verification (moved to `semgrep --test`) | MCP read/write servers and HMAC tokens: in Actions the boundary is "models get no token, code does every write", and merging a PR is the approval |
| `llm_client` (Anthropic + OpenAI-compatible, cache, spend cap) | Terminal gates (the local CLI keeps a simple y/n for `rulebook rules`) |
| Red-team cases and golden-set eval, ported to several languages | Replay-only demo mode |

The MCP server can come back in v2 as `rulebook mcp`, so IDE agents (Claude Code, Cursor) can run a review locally with the same rules.

## Repo layout

```
action.yml                 Docker container action -> ghcr.io/hrashid13/rulebook-agents:<version>
Dockerfile
pyproject.toml             package "rulebook-agents", CLI "rulebook"
src/rulebook/
  cli.py                   rulebook review | rules | test | file-issues
  action.py                reads the GitHub event, picks the flow
  policies.py              policies.md parser, ids, hashes
  semgrep.py               run, --test, changed-line filter
  diff.py                  changed lines from git
  triage.py                Agent 1
  explain.py               Agent 2
  synthesize.py            rule synthesizer
  github.py                comments, checks, PRs, issues (plain code; the only writer)
  render.py                comment markdown, escaping
  llm.py, guardrails.py
tests/                     unit tests; fixture repos per language
eval/                      golden sets per language, red-team cases
examples/                  sample policies.md and workflow
```

## Milestones

| | What | Done when |
